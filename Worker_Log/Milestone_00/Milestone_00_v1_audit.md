## Extension walkthroughs

For an environment-dependent energy, the implementation changes within `embeddings/<provider>.py` and any required `models/<provider>.py`, its builder dispatch in `hybrid.py`, declared `capabilities.py` metadata, and provider/ledger validation. It must differentiate every influencing real MM coordinate and rebuild geometry-dependent inputs after each map. A provider needing extra undeclared state requires an explicit versioned contract extension. Existing `schema.py` force semantics, protocol descriptions, `geometry.py`, `routing.py`, `atm.py`, raw-observable storage and common `analysis.py` require no environment-name branch. G02-05/06/07 detect omitted MM forces, stale mapped inputs and evaluation-order dependence; G04-06 checks the cap/MM cross derivative. These probes establish architectural behavior, not electrostatic physics.

For two unequal noncontiguous mobile molecules, `protocols/rbfe.py` validates two complete disjoint groups and emits opposite fixed translation maps plus endpoint/correction meaning. `adapters/atom.py` may change for the upstream class/key translation. The request includes both ligands in the fixed partition, without changing physical-builder code. Shared group records, full-force results, physical/model implementation, `geometry.py`, `routing.py`, `atm.py` and common analysis must retain their existing generic semantics. Neither an atom-pair mapping nor a required-first/optional-second ligand field belongs in the core. G01 checks identity, records and imports; G02-04 supplies the actual same-assembler mapping evidence. No claim that these behavioral tests already pass is made here.

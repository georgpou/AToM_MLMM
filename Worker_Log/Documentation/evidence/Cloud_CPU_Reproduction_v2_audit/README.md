The corrected `static-inspection-v3` uses the actual inventory schema and explicitly identifies generated metadata; all artifact assertions pass.

The recorded `.diff` identifies the exact line. Preserving the fetched tag and detached HEAD yields identical archive bytes; no supplied source was changed.
- The first runtime probe over-asserted that all safe-globals were identical before/after imports. PyTorch's own Dynamo/DTensor modules register trusted types at import; the corrected probe checks the scoped `slice` allowance and records those package defaults. Subsequent runtime probe failures establish the real A03 unsafe-variable issue, not a safe-globals defect.
- An exploratory text-only inspection encountered ELF utilities in Amber's bin directory. `amber-python-shebangs.json` distinguishes compiled utilities from Python scripts and verifies the latter's separate Amber interpreter. No Amber utility repair was needed.
- Missing/corrupt artifact probes returning 1 are expected negative-test observations. `controlled-failures` returning 0 means all five assertions passed; it never relabels those underlying failures as successful installations.
- `loading-policy-original` returning 1 is the intended A03 regression, after all weight-free numerical smoke checks pass. The scratch candidate returning 0 is a minimal-repair experiment, not a production patch or independently accepted repair.
- The first final documentation/delivery checks ran before generating the linked delivery hash manifest, producing one temporary new link error. Manifest generation resolves that delivery-order issue; the v2 final checks preserve the same two original errors and all eight passing self-tests. The first outputs remain available as diagnostic history.
